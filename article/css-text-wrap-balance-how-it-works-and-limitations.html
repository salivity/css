CSS text-wrap: balance: How It Works and Limitations

This article explains the CSS text-wrap: balance property, detailing the underlying algorithm that distributes text evenly across lines to avoid awkward typographic orphans. It also examines the computational reasons why browsers impose strict line limits on this rule, reserving it exclusively for headings and short text blocks rather than full-length paragraphs.

What is text-wrap: balance?

In traditional web typography, browsers use a "greedy" line-breaking algorithm. This approach fits as many words as possible onto each line before wrapping to the next. While efficient, it often leaves a single dangling word—known as an orphan or widow—on the final line of headings, creating visually unappealing and unbalanced layouts.

The text-wrap: balance property instructs the browser to distribute text evenly across all lines within a container. Instead of maximizing words on early lines, it equalizes line lengths to produce a harmonious, symmetrical block of text.

How the Balancing Algorithm Works

Unlike the standard line-wrapping mechanism, the balancing algorithm is iterative and relies on binary search techniques to achieve visual symmetry:

  1. Calculating the Initial Line Count: The browser first runs a standard layout pass using the greedy algorithm to determine the minimum number of lines required to display the text within the element's container width.
  2. Binary Search for Minimum Width: Once the line count is known, the engine performs a binary search to find the narrowest possible line width that still maintains that exact line count.
  3. Evaluating Break Points: The layout engine repeatedly tests candidate widths, measuring word widths and checking potential break opportunities until it discovers the optimal width where line lengths are as close to equal as possible without adding extra lines.
  4. Rendering the Output: After settling on the balanced boundary, the browser lays out the text according to this calculated width, centering or aligning the balanced lines within the original parent container.

Why is it Limited to Short Headline Elements?

Although balanced text looks aesthetically pleasing, browsers limit the application of text-wrap: balance—typically falling back to standard wrapping if the element exceeds roughly four to six lines. This limitation exists for two primary reasons: computational performance and typographic readability.

Computational Performance and Layout Cost

The standard greedy algorithm is computationally lightweight, operating in linear time \(O(N)\), where \(N\) is the number of words. The browser only needs a single pass through the text string to determine where each line should break.

In contrast, the balancing algorithm requires multiple layout passes to test line boundaries. Calculating text metrics involves complex font shaping, kerning, and word measurement. If applied to lengthy body text:

  • Layout Thrashing: Running multiple measurement passes on large blocks of text dramatically increases the cost of page rendering.
  • Scroll and Resize Latency: When a viewport is resized or dynamic content updates, recalculating balanced paragraphs causes severe frame drops and noticeable lag.
  • Exponential Combinations: As word count and line count grow, the search space for optimal break points expands, introducing a significant performance penalty for modern rendering engines.

To protect page speed and maintain a 60-to-120 fps rendering loop, browser engines like Chromium place a hard ceiling (typically 6 lines) on elements styled with text-wrap: balance. If an element exceeds this threshold, the engine discards the balancing algorithm and immediately falls back to standard line wrapping.

Typographic Readability

From a design perspective, balanced text is beneficial for headlines, captions, banners, and tooltips, where visual hierarchy and neatness are critical.

In body copy, however, uneven right margins across many lines disrupt a reader's natural rhythm. Predictable, consistent line lengths help the eye quickly jump to the start of the next line. Balancing long paragraphs degrades this reading flow, making body text harder to scan and consume.
