How CSS Custom Properties Update in DOM Subtrees

CSS custom properties (often called CSS variables) dynamically propagate changes through the DOM using standard CSS inheritance, cascade algorithms, and targeted style invalidation. When a custom property is overridden on a descendant element or class, the browser establishes a new scoped context for that specific DOM subtree. Any child elements inside that subtree that consume the variable via var() automatically recompute their final rendered values based on the newly defined value, without affecting ancestor or sibling branches.

The Cascade and Scope Resolution

CSS custom properties operate under the exact same inheritance rules as traditional CSS inherited properties like color or font-family. Their values resolve per element rather than globally across the stylesheet:

  1. Root Definition: A property declared at :root or on the <html> element is placed at the top of the inheritance chain and cascades down through every node in the DOM.
  2. Local Overrides: When an element with a specific class defines the same property name (e.g., .card { --theme-color: blue; }), the cascade selects this definition as the winning declaration for that element because it has a closer scope in the DOM tree than ancestors.
  3. Subtree Inheritance: Every descendant node underneath the overriding element inherits the new value by default, unless another descendant further down the hierarchy overrides it again.

The Style Invalidation Engine

When a class containing a custom property override is applied or toggled dynamically (via JavaScript, pseudo-classes like :hover, or media queries), browser rendering engines (such as Blink or Gecko) execute an optimized recalculation sequence:

1. Invalidation Flagging

The engine identifies that the computed style of the target element has changed. Instead of triggering a global recalculation for the entire document, the browser marks only the target element and its descendant subtree as dirty (requiring style recalculation).

2. Computed Value Calculation

CSS custom properties do not evaluate var() functions until computed style resolution. The engine walks down the dirty subtree:

  • It assigns the overridden value to the node defining the class.
  • It passes this resolved token to all immediate child nodes.
  • It recalculates any standard CSS properties (such as background-color, border, or transform) that consume the custom property through var().

3. Rendering Pipeline Execution

Once the new computed values are established:

  • If the affected properties only alter visual elements (like color or opacity), the browser triggers a repaint or compositing pass for the subtree.
  • If the properties alter geometry (like padding, width, or font-size), the browser triggers a reflow (layout pass) limited to the structural boundary established by the updated elements.

Code Example: Subtree Scope Isolation

Consider this markup structure:

<div class="app">
  <p>Inherits from app</p>
  <div class="theme-override">
    <p>Inherits from theme-override</p>
    <div>
      <p>Inherits from theme-override</p>
    </div>
  </div>
  <p>Inherits from app</p>
</div>

Accompanied by this CSS:

.app {
  --accent: #10b981;
}

.theme-override {
  --accent: #f43f5e;
}

p {
  color: var(--accent);
}
  • Elements matching .app > p read --accent as #10b981.
  • Elements matching .theme-override p inherit --accent as #f43f5e.
  • The final sibling p outside .theme-override continues reading #10b981 because the override is scoped exclusively to the descendant chain of .theme-override.

Dynamic Variable References (var() Dependencies)

If an overridden variable is used within another custom property, the dependency dynamically cascades down the subtree as well:

:root {
  --base-size: 16px;
  --spacing: calc(var(--base-size) * 1.5); /* 24px */
}

.compact {
  --base-size: 10px; /* --spacing dynamically resolves to 15px inside .compact */
}

.box {
  padding: var(--spacing);
}

Because custom property evaluation occurs per element during computed style time, descendant elements inside .compact recalculate --spacing using the localized --base-size of 10px, resulting in 15px of padding for .box without needing to re-declare --spacing explicitly.

Performance Characteristics

Because CSS custom properties are tied to the DOM tree's hierarchical structure:

  • Targeted Recalculations: Overriding a property on a leaf node or small subtree avoids the performance cost of broad document restyling.
  • No Preprocessing: Changes occur in real time within the browser's C++ rendering layer, bypassing the need to recompile stylesheets or alter inline styles on multiple child elements.
